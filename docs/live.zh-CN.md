# 实时分析

把摄像头对准球场开打，同一 Wi-Fi 下的手机、平板或电脑都能实时看到回合计时、拍数、球员跑动和站位。分析由一台电脑完成，观看只需要浏览器。

场边没有电脑？[只用手机](#只用手机不需要电脑)会在手机上完成全部分析。

实时分析是打球时的即时反馈。要得到可编辑的精彩集锦，请同时录像，结束后在 Studio 里跑完整的离线分析。离线流程处理每一帧，结合比赛声音和整段视频的上下文，结果仍以它为准。

## 开始实时分析

先按主 README 安装视觉依赖和模型，然后在负责分析的电脑上启动实时服务：

```bash
smart-badminton live --library /path/to/matches --host 0.0.0.0
```

终端会打印访问地址，例如 `http://192.168.1.20:8765`。在电脑上打开，或者在同一网络的手机上打开，就能在场边观看。正常的 Studio 会话里，顶栏的 **实时分析** 按钮会打开同一个页面；要让其他设备访问 Studio，需要用 `--host 0.0.0.0` 启动。

选择画面来源：

| 来源 | 适用场景 | 填写内容 |
| --- | --- | --- |
| 本机摄像头 | 分析电脑上的摄像头或 USB 摄像头 | 摄像头编号，通常是 `0` |
| 这台设备的摄像头 | 手机拍摄，电脑分析 | 不用填；需要 HTTPS（见下文） |
| 视频流或文件 | 网络摄像头 App、RTSP 摄像头，或把录像当作直播回放 | `rtsp://…`、`http://手机IP:8080/video` 或文件路径 |

再选择 **单打** 或 **双打**。双打时每边跟踪两名球员。

### 用手机当摄像头

手机浏览器只允许 HTTPS 页面使用摄像头。用本地证书启动：

```bash
smart-badminton live --library /path/to/matches --host 0.0.0.0 --https
```

在手机上打开打印出的 `https://` 地址。浏览器会提示一次自签名证书，确认信任这个地址即可。选择 **这台设备的摄像头** 后开始。手机每秒向电脑发送约 8 帧画面和麦克风声音。勾选 **同时录像** 时，手机会保存一份带声音的原画质录像，按 **结束** 后上传到素材库的 `Live/` 文件夹，之后可以在 Studio 里做完整分析。

网络摄像头 App（例如提供 `http://手机IP:8080/video` 的应用）不需要 HTTPS，在 **视频流或文件** 中填写它的地址即可。

## 只需校准一次

某个机位第一次使用时，Studio 会显示一帧静止画面。依次点击**单打**边线与底线的四个交点：近左、近右、远右、远左。Studio 会据此推算球场轮廓（单打或双打）、两个半场、球网和羽球飞行空域，之后所有位置都以米为单位计算。摄像头移动后需要重新校准。

如果 Studio 已经有同一机位的校准，点 **使用 Studio 的校准** 即可直接复制。

**角不在画面里。** 摄像头放在场边或位置较低时，常常拍不到四个角。这时选 **角不在画面里**，改为标出任意 4 个以上看得清的场地点：先在小场地图上选点（网柱底部、前发球线的两端和中点、底线的角和中点），再在画面里点它的位置。这些点不能都在同一条线上。Studio 会用它们拟合球场，并推算出四个角的位置，即使角在画面外也可以。如果有的点和其他点对不上，Studio 会拒绝保存，这通常说明某个点选错了名字。

把摄像头架高，放在一侧底线后方，让整片场地都在画面里，尽量避免广角畸变。

## 实时分析测量什么

- **回合状态和时长。** 回合的开始和结束依据羽球飞行，有声音时还会结合回合模型对击球声的判断。模型需要约 2 秒上下文，所以会稍有延迟；羽球飞行能让计时更早开始。
- **每回合拍数和每位球员的击球数。** 羽球换边，或者挥拍的手腕碰到羽球时计一拍。实时帧率下这是估计值，离线的接触分析更精确。
- **球员跟踪。** 每名球员都有稳定的编号（近场 1、近场 2、远场 1、远场 2），双打搭档交叉跑位或相互遮挡时也不会弄混。跑动距离、当前速度和最高速度都基于校准后的球场米制坐标。
- **挥拍。** 每名球员的快速手腕动作。

## 只用手机（不需要电脑）

本机模式在手机浏览器里完成姿态跟踪、击球声识别和回合判断。画面和声音都不会上传；页面加载完成后，不需要电脑，也不需要 Wi-Fi。打开部署好的 Studio 网页（`studio-web` 的网页版，例如部署在 Vercel 上），点顶栏的 **实时分析**，或者在地址后面加上 `?engine=device`。选择单打或双打，允许使用摄像头和麦克风，然后按上文校准。校准会保存在这部手机上。

能测量的内容：每名球员的编号、站位、跑动距离、速度和挥拍；击球（击球声必须在 0.2 秒内对上本场球员的挥拍，所以隔壁场地的声音和说话声不会计入）；回合（发球往返开始，2.6 秒没有击球即结束）。本机模式不跟踪羽球，拍数依赖听到击球声：场馆很吵或麦克风被挡住时，只有很用力的挥拍才会计入。

速度来自只在球员所在的位置运行姿态模型。每名已跟踪的球员只取一块 192 像素的裁剪图，而不是整帧；只有跟丢球员时，或每隔 3 秒，才重新扫描半场。手机有 GPU 时通过 WebGPU 使用 GPU（iOS 26 及以上的 Safari、较新的 Chrome），这样更快；否则用 CPU（保留一个核心），并使用 8 位量化模型（3.4 MB，而不是 12 MB，手腕精度基本不变）。启动时会实测两种方式，保留更快的那个。在没有 GPU 的四核笔记本 CPU 上，浏览器里约为每秒 17 帧。画面下方的标签会显示你的手机实际使用的方式、帧率和推理耗时。

长时间使用时请给手机接上电源或充电宝：摄像头和推理一直运行会很耗电。

**部署网页。** 页面需要 HTTPS（才能用摄像头），以及两个响应头（才能多线程推理）：`Cross-Origin-Opener-Policy: same-origin` 和 `Cross-Origin-Embedder-Policy: require-corp`。`studio-web/vercel.json` 已经设置好。两个 ONNX 模型由校验过的姿态模型导出：

```bash
smart-badminton install-models --directory models
pip install "smart-badminton[ondevice]"
smart-badminton export-ondevice-models --directory models
```

在 `studio-web` 里运行 `npm run build` 会把它们复制进网站。本地没有模型的构建（例如 Vercel）会从 `ONDEVICE_MODELS_URL` 下载；不设置时默认从本仓库最新的 GitHub Release 下载，Release 会发布 `yolo11n-pose.onnx` 和 `yolo11n-pose-int8.onnx`。手机第一次打开后会缓存模型。这两个模型和原始姿态模型一样采用 AGPL-3.0 许可，见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

## 速度与准确度

找到所有球员之后，姿态模型只在每名球员周围取一块 256 像素的裁剪图运行，而不是处理两个半场；只有跟丢球员时，或每隔 3 秒，才重新扫描整个半场。在四核笔记本 CPU 上，只开姿态时从每秒 11 帧提高到 19 帧，位置与整场扫描相差约 0.1 米；同时跟踪羽球时从 6.4 帧提高到 7.6 帧（这时较慢的是整帧的羽球检测）。`--pose-focus-size 0` 可以恢复每帧扫描半场。NVIDIA GPU 会用半精度运行两个模型，可以跟上摄像头帧率。CPU 上可以用准确度换速度：

- 降低推理尺寸：`--pose-size 384 --shuttle-size 512`（姿态从 640 降到 480 已能减少约 40% 耗时；再小会损失远场细节）；
- 取消勾选 **跟踪羽球**，或用 `--no-shuttle` 启动（这时回合判断依赖回合模型）；
- Intel CPU 上导出 OpenVINO 版姿态模型可能更快：`yolo export model=models/yolo11n-pose.pt format=openvino`，再用 `--pose-model` 传入导出的文件夹。请对照页面上的帧率判断；我们测试时 ONNX 导出并不比 PyTorch 快。

实时页面会显示实际分析帧率。电脑忙不过来时多余的帧会直接丢弃而不是排队，所以画面始终是最新的。
